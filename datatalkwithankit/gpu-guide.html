Which GPU should you rent for LLM inference?

AD
Ankit DongareCovers 7 data-center GPUs. Updated every quarter.

The short version

  1. Size the memory first. Token generation is memory-bound, so capacity and bandwidth matter more than peak FLOPS.
  2. Fit on one GPU if you can. It removes tensor parallelism, synchronization, and most failure modes. The 256 to 288 GB GPUs (MI325X, B300, MI355X) fit much more on one device.
  3. If you need several GPUs on one model, pay for the interconnect. NVLink nodes scale better than PCIe cards.
  4. Compare the bill, not the hourly rate. Minimum node sizes, egress, preemption, and idle time change the real cost.

Step 1: How many GPUs does your model need?

Weights take about 2 bytes per parameter at FP16 and about 1 at FP8. On top of that you need room for the KV cache, which grows with batch size and context length. I add 20% headroom as a starting point. Long contexts or big batches need more.

Counts round up to 1, 2, 4 or 8, because tensor parallelism splits a model evenly across GPUs. Above 8 means more than one 8-GPU node.

Try other sizes, including INT4, in the will-it-fit calculator.

Step 2: Compare the specs that matter for inference

Because decode is memory-bound, bandwidth sets the ceiling on tokens per second per GPU. The H200 has 43% more bandwidth than the H100 on the same compute die. B200, B300, and MI355X all reach 8 TB/s, about 2.4 times an H100.

Step 3: One GPU, or several working together?

  • Each GPU runs its own copy of the model: PCIe cards are fine. Save the money.
  • Several GPUs share one model (tensor parallelism): every layer needs an all-reduce for every token, so the GPU-to-GPU link becomes the bottleneck. NVLink 4 moves 900 GB/s per GPU and NVLink 5 doubles that to 1.8 TB/s, versus about 128 GB/s for PCIe Gen5 x16. Buy SXM nodes.
  • Scaling to 8 GPUs: in published 8-GPU training comparisons of H200 and MI300X, NVLink nodes reached around 87% scaling efficiency versus roughly 78% for MI300X.

Before you commit, check four things that change the real cost:

  • Minimum node size. Some providers only sell full 8-GPU nodes.
  • Egress. Moving weights and data out can erase the savings.
  • Preemption. Cheap is often spot, which is bad for anything user-facing.
  • Utilization. A GPU you rent and don't keep busy is the most expensive one.
