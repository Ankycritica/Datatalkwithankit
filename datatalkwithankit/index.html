Bio

I'm an AI engineer focused on the practical side of large language models: how they're served, how fast they run, what they cost, and how configuration choices change all three. Day to day, that means building and evaluating LLM inference systems — benchmarking models, tuning serving stacks like vLLM, and turning results into decisions.

My path started in data. I began as a data analyst turning messy tables into answers, and kept following the harder questions until they led to building AI systems full-time. That origin still shapes how I work: I trust measurements over vibes, and I'd rather show you a benchmark than an opinion.

I'm automation-first by habit. If I do something twice, I script it — from data pipelines to a fully automated video-publishing workflow. I'm not perfect, but I show up every single day and learn harder than the day before.

How batch size changes vLLM throughput: a first benchmark

This is a sample post showing the structure your write-ups can follow: motivation → setup → results → takeaways. Swap in your real experiment when you're ready.

Why this experiment

Batch size is one of the most powerful levers in LLM serving, but the tradeoff between throughput and latency is rarely shown with real numbers. This post measures it directly on a single-GPU vLLM deployment.

Setup

workload:     <prompt/output token lengths>
metric:       tokens/sec, p50 & p95 latency

How I run an experiment

Method
01 \u00b7 Question

Start from one narrow, falsifiable question \u2014 something a number can answer, not an opinion.

02 \u00b7 Setup

Fix the hardware, model, and workload. Warm up properly. Record every parameter that could move the result.

03 \u00b7 Measure

Multiple runs, report the spread \u2014 not a single lucky number. Latency gets percentiles, never averages alone.

04 \u00b7 Publish raw

Configs, scripts, and unedited results go up alongside the write-up so anyone can rerun it.

05 \u00b7 Report failures

Runs that contradicted the hypothesis get written up too. Those are usually the useful ones.

06 \u00b7 Next question

Every result raises a sharper question. That becomes the following experiment.
