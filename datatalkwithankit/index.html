Memory estimates = approximate total parameters × bytes per weight × 1.2, in decimal GB. The 20% allowance is a starting point; context length, KV cache, batching, and runtime allocations change actual fit. Counts round up to power-of-two candidates. Multi-GPU configurations also need supported parallelism and interconnects.

Precision, checkpoints, and sources

FP8 and INT4 compare memory footprints; they require an appropriate quantized checkpoint and kernels for your hardware. CUDA quantization implementations do not automatically work on AMD. Check the vLLM hardware compatibility table for the exact format and backend.

MoE memory uses all stored parameters, including inactive experts. Model names link to publisher cards with architecture, download access, and license details. DeepSeek's mixed-precision checkpoint can differ from these simplified format estimates. These are inference planning examples; they have not been benchmarked on every GPU.

About

I’m Ankit, an AI engineer based in the Washington, DC area. I started with data analytics and kept following the harder questions until they led to building AI systems full time.

Today I work on the practical side of large language models: how they're served, how fast they run, what they cost, and how configuration choices change all three. At work I benchmark and evaluate an enterprise LLM inference platform, measuring throughput, latency, and cost across models, serving configs, and hardware.

That data background still shapes how I work. I trust measurements over opinions, and if I do something twice, I write a script for it.

Day to day: Python, PyTorch, vLLM, Hugging Face, Docker, and AWS. The full list is on the uses page.
