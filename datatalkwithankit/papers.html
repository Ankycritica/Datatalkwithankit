How I run an experiment

The same six steps, every time.

  1. Ask one narrow question

    Something a number can answer, not an opinion.

  2. Fix the setup

    Same hardware, model, and workload. Warm up properly and record every parameter that could move the result.

  3. Measure the spread

    Multiple runs, reported as a range. Latency gets percentiles, never an average alone.

  4. Publish the raw data

    Configs, scripts, and unedited results go up next to the write-up.

  5. Report what failed

    Runs that contradict the hypothesis get written up too. They're usually the useful ones.

  6. Find the next question

    Every result raises a sharper question, and that becomes the next experiment.
