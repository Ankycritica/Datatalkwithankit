Project case study

From a sourced story to a published video

Ankit DongareNov 17, 2026

A video workflow has a lot of repeated work: choosing a story, checking the script, preparing audio, rendering scenes, adding captions, and publishing the result. I built a Python pipeline to connect those steps.

Project case study · Python, FFmpeg, Whisper, YouTube Data API

The problem

Automating one step is easy. Keeping the whole sequence consistent is harder. A correct script can still produce an unreadable caption, a mismatched visual, or a render that should never reach the upload queue.

The workflow

  1. Source and select.Start with a story supported by identifiable sources. Keep the supporting facts with the script.
  2. Write and check.Turn those facts into narration, then check the claims before making media.
  3. Render and caption.Generate narration, build the video with FFmpeg, and align captions with Whisper.
  4. Review and publish.Check the completed output before passing it to the YouTube publishing workflow.

Where the engineering matters

The useful part is the handoff between stages. Keeping source information, scripts, audio, and rendering outputs organized makes a failed step easier to inspect and repeat. Quality checks belong before publishing, where they can stop a problem from becoming a public video.

The system handles repetitive production work. Editorial judgment still matters: a functioning render does not tell you whether the story is interesting, the framing is fair, or the video will earn an audience.

What this project demonstrates

  • Orchestrating several media tools in a repeatable Python workflow.
  • Carrying source-backed facts through script and production stages.
  • Connecting rendering, captioning, and a publishing API with review points.

This case study describes the workflow. The production repository is private, so there is no public source-code download for this project.
